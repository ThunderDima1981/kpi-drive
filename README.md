# KPI-Drive

Веб-приложение для мониторинга коэффициента результативности (КР) по матрице MBO Литягина. Считает только выполнение показателей. Оклады, зарплаты и денежные премии в модель не входят.

Данные команды хранятся в `localStorage` браузера. При первом открытии загружается демонстрационная команда: Иванов Иван и ещё четыре матрицы. Сидоров Алексей в иерархии подчинён Иванову: ветка открывается по «+», поиск над списком оставляет совпадения и их руководителей.

## Запуск

```bash
npm install
npm run dev
```

Приложение откроется на [http://127.0.0.1:4317](http://127.0.0.1:4317).

Проверка расчёта:

```bash
npm test
```

Сборка:

```bash
npm run build
```

## Как устроен КР

Сумма весов матрицы может быть меньше 100%: сверху остаётся предупреждение, и вклад показателей всё равно считается. Сохранить сумму больше 100% нельзя.

КР = сумма по всем показателям (`% выполнения × вес / 100`).

- Количественный KPI живёт в общем справочнике. План, факт и точки шкалы одни на всех сотрудников; в матрице у показателя только свой вес. На графике точки задаются вручную: значение факта и процент выполнения. Демо-шкала по-прежнему строится из порога (0%), плана (100%) и максимума (130%).
- Smart-задачи — один показатель матрицы со своим весом. Внутри блока у каждой задачи свой вес, и сумма этих весов может быть больше 100%. Процент выполненных задач — сумма весов закрытых задач. График переводит этот процент во влияние на вес блока: по умолчанию 0% → 0%, 100% → 100%, 200% → 130%. Вклад в КР = влияние × вес блока / 100. Статус «Закрыт» даёт задаче 100%, любой другой статус — 0%. У задачи есть подробный комментарий, критерий оценки и список комментариев.
- Стандарт: по умолчанию −2 = 0%, −1 = 70%, 0 = 100%, +1 = 115%, +2 = 130%. На графике можно менять точки и процент выполнения каждой. У каждого стандарта есть оценщик — сотрудник из команды.
