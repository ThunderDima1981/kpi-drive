# KPI-Drive

Веб-приложение для мониторинга коэффициента результативности (КР) по матрице MBO Литягина. Считает только выполнение показателей. Оклады, зарплаты и денежные премии в модель не входят.

Данные команды хранятся в PostgreSQL и принадлежат учётной записи, под которой выполнен вход. Новая учётка начинает с пустой команды и правами администратора. Администратор открывает настройки, собирает матрицу и меняет её параметры. Пользователь может только создавать smart-задачи и ставить им статус «Выполнено». В настройках администратор связывает учётную запись с сотрудником и отмечает матрицы, которые ей доступны. Пользователь видит только эти матрицы. Администратор видит всю свою команду. Последнего администратора нельзя понизить или удалить. Период выбирается месяцем и годом: все матрицы, планы, факты, статусы smart-задач и оценки стандартов относятся к выбранному месяцу. Иерархия раскрывается по «+», поиск над списком оставляет совпадения и их руководителей.

## Запуск

Нужен PostgreSQL. Локально приложение само подключается к `postgres://kpi:kpi@127.0.0.1:5432/kpi_drive`. Другой адрес задаётся переменной `DATABASE_URL` (см. `.env.example`).

```bash
npm install
npm run dev
```

`npm run dev` проверяет локальный PostgreSQL, при необходимости запускает его, затем поднимает API на порту 4327 и интерфейс на [http://127.0.0.1:4317](http://127.0.0.1:4317). Запросы к `/api` проксируются на API. Сначала откроется вход или регистрация.

Проверка расчёта:

```bash
npm test
```

Сборка:

```bash
npm run build
```

## Как устроен КР

Сумма весов матрицы может быть меньше 100%: сверху остаётся предупреждение, и вклад показателей всё равно считается. Сохранить сумму больше 100% нельзя.

КР = сумма по всем показателям (`% выполнения × вес / 100`).

- Количественный KPI живёт в общем справочнике. План, факт и точки шкалы одни на всех сотрудников и свои у каждого месяца. План задаётся в справочнике: это точка шкалы со 100% выполнения. В матрице у показателя только свой вес. На графике точки задаются вручную: значение факта и процент выполнения. Новая шкала начинается с порога (0%), плана (100%) и максимума (130%).
- Smart-задачи — один показатель матрицы со своим весом. Внутри блока у каждой задачи свой вес, и сумма этих весов может быть больше 100%. Процент выполненных задач — сумма весов закрытых задач. График переводит этот процент во влияние на вес блока: по умолчанию 0% → 0%, 100% → 100%, 200% → 130%. Вклад в КР = влияние × вес блока / 100. Статус «Закрыт» даёт задаче 100%, любой другой статус — 0%. У задачи есть подробный комментарий, критерий оценки и список комментариев.
- Стандарт: по умолчанию −2 = 0%, −1 = 70%, 0 = 100%, +1 = 115%, +2 = 130%. На графике можно менять точки и процент выполнения каждой. У каждого стандарта есть оценщик — сотрудник из команды.
