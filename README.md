# KPI-Drive

Веб-приложение для мониторинга коэффициента результативности (КР). Считает только выполнение показателей. Оклады, зарплаты и денежные премии в модель не входят.

Данные команды хранятся в PostgreSQL и принадлежат учётной записи, под которой выполнен вход. Первая учётная запись становится администратором. После этого регистрация закрыта: новые люди входят только по приглашению. Администратор в «Настройки → Пользователи» указывает почту, права, сотрудника и матрицы. Человек получает письмо со ссылкой на 7 дней, сам вводит имя и пароль. Если почта не настроена, ссылку можно скопировать и передать вручную. После 5 неверных паролей подряд вход блокируется на 15 минут. Блокировку снимает восстановление пароля или новый пароль от администратора. «Забыли пароль?» на экране входа присылает ссылку на час, по ней пользователь задаёт новый пароль. Если два администратора правят одни данные, второе сохранение не затирает первое: страница показывает, кто успел изменить данные, и загружает актуальную версию. Администратор открывает настройки, собирает матрицу и меняет её параметры. Смарт, который создаёт сотрудник, получает статус «Создан»: в работу его переводит руководитель или администратор. Сотрудник ставит «Выполнено» только из статуса «В работе». Если смарт создаёт руководитель, он сразу «В работе». Статус «Закрыт» ставит только руководитель сотрудника. Кнопку «На следующий месяц» видит только прямой руководитель: задача уходит в следующий месяц и исчезает из текущего. У каждой учётной записи может быть фото. Администратор загружает его в «Пользователях» (нажать на аватар или «Изменить»), пользователь — нажав на свой аватар внизу меню. Картинка обрезается до квадрата 320×320 прямо в браузере. Фото видно у связанного сотрудника везде, где он показан: на дашборде, в иерархии, в матрице, в «Сотрудниках» и в «Заполнить оценки». Меню «Настройки» разделено на сотрудников, количественные показатели, пользователей, почтовый сервер и журнал. «Журнал» видят только администраторы. В нём записано, кто и когда менял матрицы, показатели, статусы смартов, оценки, пользователей, приглашения и почту. Правки одного человека за 5 минут собираются в одну запись. Письма о создании и смене статуса smart-задачи уходят сотруднику и руководителю, если к ним привязана учётная запись. Пункт «Заполнить оценки» виден тому, кто назначен оценщиком другого сотрудника. В показателях и пользователях администратор скачивает шаблон Excel и загружает файл. В пользователях администратор связывает учётную запись с сотрудником и отмечает матрицы, которые ей доступны. Пользователь видит только эти матрицы. Администратор видит всю свою команду. Последнего администратора нельзя понизить или удалить. Период выбирается месяцем и годом. Новый месяц копирует состав матрицы; дальше она меняется только в открытом месяце. План, факт и оценка стандарта у каждого месяца свои. Smart-задачи в новом месяце создаются заново. Если смарт сохранил другой человек, открытое окно получает его без перезагрузки страницы. Иерархия раскрывается по «+», поиск над списком оставляет совпадения и их руководителей.

## Запуск

Нужен PostgreSQL. Локально приложение само подключается к `postgres://kpi:kpi@127.0.0.1:5432/kpi_drive`. Другой адрес задаётся переменной `DATABASE_URL` (см. `.env.example`).

```bash
npm install
npm run dev
```

`npm run dev` проверяет локальный PostgreSQL, при необходимости запускает его, затем поднимает API на порту 4327 и интерфейс на [http://127.0.0.1:4317](http://127.0.0.1:4317). Запросы к `/api` проксируются на API. Сначала откроется вход или регистрация.

Проверка расчёта:

```bash
npm test
```

Сборка:

```bash
npm run build
```

## Сервер Ubuntu

Боевой запуск — это PostgreSQL, собранные страницы и API. `npm run dev` на сервере не используется. `NODE_ENV=production` отключает локальную подготовку базы: роль и базу создают команды ниже. При каждом старте API само дополняет структуру таблиц и не удаляет уже введённые данные.

Обновление одной командой:

```bash
sudo bash /opt/kpi-drive/deploy/update.sh
```

Скрипт по шагам:

1. Снимает копию базы и папки сайта.
2. Забирает изменения из GitHub (`git pull`).
3. Ставит зависимости, если менялся `package.json`.
4. Собирает интерфейс.
5. Дописывает `APP_URL=https://kpi.raz2va.ru` в `.env`, если его там нет. По этому адресу строятся ссылки в письмах.
6. Устанавливает службы systemd и включает ежедневную копию.
7. Перезапускает `kpi-drive` и проверяет `/api/health`.

Каждый день около 03:30 таймер `kpi-drive-backup.timer` запускает `deploy/backup.sh`. Скрипт снимает две копии в `/var/backups/kpi-drive`, по 5 последних каждого вида:

- база — `kpi-drive-<дата>.dump`;
- папка сайта без `node_modules` — `kpi-drive-site-<дата>.tar.gz`. В неё входят код, `.git`, собранный `dist` и `.env`.

Те же две копии делаются перед каждым обновлением. Снять копию вручную: `sudo bash /opt/kpi-drive/deploy/backup.sh`.

Восстановить базу: `sudo bash /opt/kpi-drive/deploy/restore.sh /var/backups/kpi-drive/kpi-drive-<дата>.dump`.

Восстановить сайт: `sudo bash /opt/kpi-drive/deploy/restore.sh /var/backups/kpi-drive/kpi-drive-site-<дата>.tar.gz`. Прежняя папка переименуется в `/opt/kpi-drive.before-restore-<дата>`, зависимости поставятся заново.

Скрипт восстановления спросит подтверждение и перед заменой сохранит текущее состояние.

Cookie входа помечается `Secure`, когда nginx передаёт `X-Forwarded-Proto: https`. Поэтому по https сеанс не уходит по открытому каналу, а локальная разработка по http продолжает работать.

## Как устроен КР

Сумма весов матрицы может быть меньше 100%: сверху остаётся предупреждение, и вклад показателей всё равно считается. Сохранить сумму больше 100% нельзя.

КР = сумма по всем показателям (`% выполнения × вес / 100`).

- Количественный KPI живёт в общем справочнике выбранного месяца. План, факт и точки шкалы одни на всех сотрудников в этом месяце и другие в следующем. План — точка шкалы со 100% выполнения; администратор меняет его в матрице и в справочнике настроек. На графике точки задаются вручную. Новая шкала начинается с порога (0%), плана (100%) и максимума (130%).
- Новый месяц копирует состав матрицы: сотрудников, показатели и веса. Факт встаёт на точку 0% шкалы, оценки стандартов — на 0, список smart-задач пустой.
- Smart-задачи — один показатель матрицы со своим весом. Внутри блока у каждой задачи свой вес, и сумма этих весов может быть больше 100%. Процент выполненных задач — сумма весов закрытых задач. График переводит этот процент во влияние на вес блока: по умолчанию 0% → 0%, 100% → 100%, 200% → 130%. Вклад в КР = влияние × вес блока / 100. Статус «Закрыт» даёт задаче 100%, любой другой статус — 0%. Сотрудник создаёт задачу со статусом «Создан», руководитель или администратор переводит её в «В работе», сотрудник отмечает «Выполнено», руководитель ставит «Закрыт». «На следующий месяц» доступна только прямому руководителю сотрудника. Задача переносится с тем же статусом: если следующего месяца ещё нет, он создаётся с тем же составом матрицы. У задачи есть подробный комментарий, критерий оценки и список комментариев.
- Стандарт: по умолчанию −2 = 0%, −1 = 70%, 0 = 100%, +1 = 115%, +2 = 130%. На графике можно менять точки и процент выполнения каждой. У каждого стандарта есть оценщик — сотрудник из команды.
